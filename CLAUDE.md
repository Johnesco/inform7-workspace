# Inform 7 Game Workspace

This folder holds Inform 7 games and Z-machine stories (classic Infocom format, e.g. zork1-v0). Both play through the same Parchment player. Each subfolder is its own git repo, built and tested here, and published to GitHub Pages through IF Hub. The tooling in `tools/` is self-contained; it does not depend on the hub.

## Authoring

- Source file: `story.ni`. First line must be `"Title" by "Author"`.
- Use `[apostrophe]` not `'` in I7 strings.
- Use `After printing the banner text` for custom attribution (never `When play begins`).
- No colons in game titles (Windows filename limitation).
- Config for the hub: `ifhub.conf` (engine, title, author, description, tags, source, walkthrough, sound).
- Test config: `tests/project.conf` (interpreter paths, score patterns, walkthrough, regtest file).

Language references are in `reference/`: `syntax-guide.md`, `text-formatting.md`, `world-model.md`, `understanding.md`, `rulebooks.md`, `activities-phrases.md`, `verb-help.md` (the verb help system; template at `tools/verb-help-template.ni`), `sound.md` (native blorb sound), `recipe-book.md`, `writing-with-inform.md`, and the I7 handbook PDFs. Player debugging: `reference/parchment-troubleshooting.md`, `reference/glk-styling.md`, `reference/build-pipeline.md` (manual compile steps), `reference/windows-pitfalls.md`.

## Compiler

Inform 7 is installed system-wide (override the location with `INFORM7_HOME`):

- I7: `C:\Program Files\Inform7IDE\Compilers\inform7.exe`
- I6: `C:\Program Files\Inform7IDE\Compilers\inform6.exe`
- inblorb: `C:\Program Files\Inform7IDE\Compilers\inblorb.exe`
- Internal: `C:\Program Files\Inform7IDE\Internal`

Do NOT create `.inform/` IDE bundles; `tools/compile.py` compiles with `-source` and `-o`.

## Build and test

```bash
python tools/build.py <game>                 # compile + tests + Parchment player + tests.html
python tools/build.py <game> --no-test       # compile + player only
python tools/build.py <game> --compile-only  # binary only
python tools/build.py <game> --force         # overwrite play.html (keep a play-template.html to protect a custom player)
```

`build.py` runs `compile.py` (I7 to I6 to Glulx; a `.gblorb` when `ifhub.conf` says `sound = blorb` or a `Sounds/` folder exists; then `web/setup_web.py` for the Parchment player), then the tests: the walkthrough through `run_walkthrough.py` with the golden seed from `tests/seeds.conf`, `generate-guide.py` for the annotated guide, regtests through `run_tests.py --json` converted to `test-results.json` and rendered to `tests.html` in ifPlayer's format, and any `tests/*.test` files through `python -m ifplayer.cli test`.

**Z-machine stories** (`engine = zmachine` in `ifhub.conf`): `build.py` skips the compiler and tests, copies the Parchment libraries into `lib/parchment/`, encodes the story file named by `binary =` (a `.z3`/`.z5`/`.z8`, or an already encoded `.js` used as-is), and writes `play.html` from the Parchment template. A `play-template.html` in the game folder takes precedence, which keeps a customised player safe under `--force` (zork1-v0 has one; give it a template before forcing).

Individual tools (most take `--config tests/project.conf`): `run_walkthrough.py`, `run_tests.py`, `run_scenarios.py`, `find_seeds.py`, `find_scenario_seeds.py`, `generate-guide.py`, `extract_commands.py` (walkthrough from a transcript or `Test me`), `generate_map.py` (room map from a walkthrough), `explore.py` (tree exploration), `new_project.py` (scaffold a game), `validate_web.py`, `regtest.py` (Plotkin's RegTest), `testing-dashboard.py`.

Interpreters: `tools/interpreters/glulxe.exe` and `dfrotz.exe` (native Windows, built with `tools/interpreters/build.sh` under MSYS2). `tests/project.conf` files refer to them as `$_IFHUB_ROOT/tools/interpreters/...`; that variable now resolves to this workspace root.

ifPlayer lives at `C:\code\text-games\ifPlayer\` (installed with `pip install -e .`).

## Game structure

```
<game>/
├── ifhub.conf               # what IF Hub reads
├── story.ni                 # source
├── <game>.ulx / .gblorb     # compiled (generated)
├── play.html                # Parchment player (generated; customise via play-template.html, not directly)
├── lib/parchment/           # player libs + encoded story (generated)
├── walkthrough.txt, walkthrough_output.txt, walkthrough-guide.txt   # copied from tests/inform7/ by the build
├── tests.html, test-results.json                                    # generated by the test stage
├── index.html, source.html, walkthrough.html                        # written by the hub's ship.py
└── tests/
    ├── project.conf, seeds.conf
    ├── inform7/walkthrough.txt      # canonical walkthrough
    ├── *.regtest / *.scenario, scenarios/
    └── *.test                       # ifPlayer tests (optional)
```

## Publish

```bash
python C:/code/ifhub/tools/ship.py <game>           # wrapper pages + register + publish to Pages + push hub
python C:/code/ifhub/tools/ship.py <game> --local   # register only, for a local hub preview
```

Contract and details: `C:\code\ifhub\docs\publishing.md`. Skills for player debugging and Git Bash pitfalls are in `.claude/skills/`.
